# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities through public issues, discussions or pull requests.

Report them privately by either:

- Using GitHub's **Report a vulnerability** option under the repository's **Security** tab (private vulnerability reporting), or
- Emailing **hello@grydin.co**

Include as much of the following as you can:

- Type of issue (e.g. injection, authentication bypass, data exposure)
- Affected repository, file and version or commit
- Steps to reproduce, with proof of concept if available
- Potential impact

## What to expect

- Acknowledgement within 3 business days
- An initial assessment and next steps within 10 business days
- Updates as the fix progresses, and credit in the release notes if you want it

## Scope

This policy covers code in GrydIn's public repositories, including Qualifyr. It does not cover client systems, production deployments or third-party services. Do not test against systems you do not own or have permission to test.

## Responsible disclosure

- Give us reasonable time to fix the issue before any public disclosure.
- Do not access, modify or delete data that is not yours.
- Do not run denial-of-service or social engineering attacks.

We will not pursue action against good-faith research that follows this policy.

## Supported versions

Security fixes are applied to the latest release or the `main` branch only.
