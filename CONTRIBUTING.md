# Contributing to GrydIn

Thanks for your interest in contributing. This guide applies to all public GrydIn repositories unless a repo has its own CONTRIBUTING.md.

## Ways to contribute

- Report bugs
- Suggest features or improvements
- Improve documentation
- Submit code fixes or enhancements

## Reporting bugs

Open an issue and include:

- What you expected and what happened instead
- Steps to reproduce
- Your environment (OS, language/runtime version, repo version or commit)
- Logs or screenshots where relevant

Search existing issues first to avoid duplicates.

## Suggesting features

Open an issue describing the problem you want solved, not just the solution. Explain who it helps and how you would use it.

## Submitting code

1. Fork the repository and create a branch from `main` (e.g. `fix/short-description` or `feat/short-description`).
2. Keep changes focused. One pull request should address one thing.
3. Follow the existing code style and structure of the repo.
4. Add or update tests and documentation where relevant.
5. Write clear commit messages that explain what changed and why.
6. Open a pull request describing the change and linking any related issue.

For large changes, open an issue first to discuss the approach before writing code.

## Pull request review

- A maintainer will review your PR and may request changes.
- We aim to respond within a few business days, but this is not guaranteed.
- PRs that are out of scope or do not fit the project direction may be declined.

## Security issues

Do not report vulnerabilities in public issues. See [SECURITY.md](SECURITY.md) for how to report them privately.

## Licensing

By contributing, you agree that your contributions will be licensed under the same license as the repository you are contributing to.
